# ADR 0006: The demo project uses real brand names with invented data

Status: accepted 2026-09-24.

## Decision

The built-in demo project is about a real company (Ramp) with real competitors (Brex, Navan,
Mercury), so a new user sees a market they recognise. Every number, answer and perception
summary in it is generated by the demo generator, never copied from a real run, and every
page of the demo carries a permanent notice that its data is invented. All demo runs are
marked mock, and the demo's statistics are scored by the same finalisation pipeline as a real
project's, so the screens show what the app really looks like with six months of history.

The perception text is neutral and factual in tone, written from what is publicly on the record
about the company: widely published praise and criticism. It invents no events, dates or
numbers, and its downsides section reports commonly published criticisms in neutral phrasing
rather than staying empty. (Amended 2026-09-26: the earlier rule left downsides empty to avoid
inventing weaknesses of a real company; an empty section made the demo's perception band read
thin next to the rest of the page, and published criticism is on the record, not invented.) The generated history ends at the last noon UTC before the demo is
created, so a demo restored months later still reads as "the last six months".

This is the only place real brand names are allowed. Tests, fixtures, docs and screenshots
keep using the fictional roster from ADR 0002; the sole exception is tests of the demo
generator itself, which necessarily assert the demo's own names. Amended 2026-09-26: the
README's screenshots of the demo are a second exception; see the amendment below.

## Constraints

- At most one demo project exists; the database enforces it with a partial unique index.
- The demo data is generated from a fixed seed, never recorded from real provider calls.
- `CONTRIBUTING.md`'s fictional-brands rule carries a one-line exception pointing here.

## Considered options

- A fictional demo brand (for example Acme Analytics): no rule change, but an unfamiliar
  market makes the demo harder to read, and the point of the demo is that a new user
  recognises the category and the players at once.
- Recording a real project's data and shipping it: real answers about real companies raise
  accuracy and rights questions the generator avoids entirely.

## Amendment 2026-09-26: README screenshots

The README's screenshots, kept in `docs/screenshots/`, may show the demo project as it is,
real names included, and the new project screen filled in with the demo's brand and
competitors. The demo's data is generated, so nothing in those images is a measurement of a
real company. The screenshots may also leave the demo notice and the browse-only note out,
hidden when they are captured, so the pages read the way they will for a user's own brand. The
README says in plain text that its screenshots show the built-in demo project and that its
history is generated.

Nothing else changes. The app keeps the permanent notice on every demo page, the demo data
stays generated from the fixed seed, and tests, fixtures and documentation examples keep the
fictional roster from ADR 0002.
